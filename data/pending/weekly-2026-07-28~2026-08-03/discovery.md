## 🔥 信号 1: AI Agent 提示注入安全扫描器（GitLost 类）

**证据热点** (1 条，但是本周最具体的安全事件):
- [InfoQ] GitHub AI Agent 翻车：攻击者不用黑客技术，只写一句话就能窃取数据 — "GitLost" 由 Noma Security 发现，诱骗 GitHub Agentic Workflows 泄露私有数据；攻击者只需在公开 Issue 中嵌入隐藏指令即可绕过安全防护

**底层需求**: AI Agent（GitHub Copilot Agentic Workflows、读公开 issue/PR 的客服/运维 agent）正在暴露一个**全新的攻击面**：公开输入通道被提示注入。企业**不知道自己的 agent 是否暴露、暴露了哪些数据**。这是本周才被命名的漏洞类型（GitLost），意味着市场认知刚起步，工具空白。

**目标用户**: 用 GitHub Copilot Agentic Workflows 的开发团队；做 AI 客服/运维 agent 接入公开渠道的 SaaS 公司；安全合规团队

**AI 解决方案**:
- AI 能做：扫描 issue/PR/评论里的隐藏指令模式（零宽字符、HTML 注释、Unicode 同形字、语义层注入）；对 agent 的工具调用做"是否被注入"判定；红队生成攻击 payload 测试自身 agent
- 人要做：GitHub API 接入 + agent 工具调用日志采集；规则与模型结合的检测引擎

**MVP 形态**: GitHub App——装上后扫描指定 repo 的所有 issue/PR/comment，标红疑似提示注入，给出"如果你的 agent 读到这条会泄露什么"的模拟。先做检测，不做拦截。

**可行性**: 8/10 — 真实安全事件（本周命名）+ 防御性安全（合规无雷区）+ 企业付费意愿强（安全赛道天花板高）+ AI 原生检测（LLM 理解注入语义是模型强项）；扣分项是销售周期长（企业安全采购慢）、竞品会出现（Noma Security 本身就是竞品雏形）

**变现**: 企业版 ¥999/月/repo 扫描；红队测试按次计费；对标 Snyk/GitGuardian 的"AI 输入面安全"品类

**风险**:
- Noma Security（发现漏洞的厂商）本身可能产品化 → 须主打"国产化 + 中文社区 + 多 agent 平台"差异化
- 企业安全销售周期长，不适合"睡后收入"画像 → 可先做开发者开源版攒信誉，再切企业
- 提示注入检测是猫鼠游戏，攻击手法会进化 → 持续维护负担

## 🔥 信号 2: 垂直 AI 工具的 "Skills 发现/安装" 层

**证据热点** (5 条，方向一致):
- [InfoQ] 盯盘虾：用 skills 实现财报抓取 + 异动告警自动化
- [InfoQ] 家教虾：用 skills 完成海量课件解析、智能出题
- [掘金] A 社官方：我们删掉了 80% 的 skills
- [hellogithub] 让 AI 读代码画出架构图 / 在线 AI 简历编辑器 / 可多人协作的旅行规划平台（多个"用 skills/agent 做的垂直工具"集中上架）
- [掘金] 《深入理解 AI Agent：设计原理与工程实践》

**底层需求**: 越来越多人用 Claude Code / agent skills 做**垂直小工具**（盯盘、家教、画架构图、简历、旅行规划）。但发现/安装/更新这些 skills 的层是**散的**——散在 hellogithub、juejin、github、公众号，没有统一的"skills 市场"。同时 A 社（Anthropic）官方删了 80% skills，说明官方在收缩，**第三方发现层反而出现真空**。

**目标用户**: Claude Code / Cline / Cursor 用户，想找现成 skills 装上就用，不想自己写

**AI 解决方案**:
- AI 能做：从全网爬取 skills 描述 → 语义索引 → 自然语言搜索"我想盯盘"返回可用 skill；自动检测 skill 与新版本 Claude Code 的兼容性
- 人要做：skills 来源爬取与合规、安装链路（git clone / mcp install）、版本兼容检测

**MVP 形态**: 一个网站 + CLI——输入"盯盘财报异动"，返回社区 skills 列表（来源、评分、一键安装命令）。先做"发现 + 一键安装"，不做编辑器。

**可行性**: 6/10 — 多条数据同向 + A 社删 skills 留下真空是真实窗口；扣分项多：Anthropic 官方随时可能重新做市场、Claude Code skills 格式不稳定、变现难（市场类业务通常是流量生意而非付费）

**变现**: 流量广告 / skills 作者分成 / 企业私有 skills 托管（重）。**不适合睡后收入**——偏流量生意，与 Frank 画像中度契合

**风险**:
- Anthropic 官方重做 skills 市场直接碾压（最大风险）
- skills 格式随 Claude Code 改版频繁，维护成本高
- 流量生意难变现，小红书/公众号引流才是主战场，不是软件产品
- → 倾向**作为观察信号**而非立即做

## 🔥 信号 3: AI 生成代码"可维护性体检"工具

**证据热点** (2 条):
- [InfoQ] React Compiler 迁移 Rust 后更快了，但开发者担心"没人看得懂代码"
- [少数派] Vibe Coding 时代，为什么降本不一定增效？

**底层需求**: AI 自动生成/迁移的代码（React Compiler Rust 迁移、vibe coding 产出）越来越多，但**人类看不懂、难维护**。团队不知道一份 AI 生成的代码"接手成本"有多高——可读性、可调试性、魔法依赖程度都没有量化。现有代码质量工具（SonarQube/ESLint）查的是规则违反，查不了"AI 味/不可维护度"。

**目标用户**: 用 AI 写代码的团队 + 接手 AI 代码的维护者 + 技术 leader

**AI 解决方案**:
- AI 能做：判定"这段代码是否过度依赖 AI 生成的隐式模式"、复杂度与可读性打分、生成"接手这份代码需要的上下文清单"
- 人要做：检测规则集、与现有 linter 集成

**MVP 形态**: CLI + GitHub Action——对 PR 里 AI 生成/迁移的代码打"可维护性分 + 风险点清单"，挡在合并前。

**可行性**: 6/10 — 痛点真实且本周有具体事件（React Compiler）；扣分项：检测标准主观（"可维护"难量化）、竞品方向多（SonarQube 会加 AI 检测）、变现偏企业向

**变现**: GitHub Action 免费 + 团队付费；偏企业，睡后收入弱

**风险**:
- "可维护性"定义主观，难做出公认标准
- SonarQue/CodeRabbit 等已做 AI 代码 review，差异化窄
- 偏企业向，与 Frank 睡后收入画像契合度中低
