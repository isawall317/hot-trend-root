## 🔥 信号 1: AI Agent 提示注入安全扫描器（GitLost 类）

**category**: tech | **可行性**: 8/10

**证据热点** (1 条，本周最具体的安全事件):
- [InfoQ] GitHub AI Agent 翻车：攻击者不用黑客技术，只写一句话就能窃取数据 — "GitLost" 由 Noma Security 发现，诱骗 GitHub Agentic Workflows 泄露私有数据

**底层需求**: AI Agent（读公开 issue/PR 的客服/运维/Copilot agent）暴露全新攻击面——公开输入通道被提示注入。企业不知道自己的 agent 是否暴露。本周刚命名，工具空白。

**目标用户**: 用 GitHub Copilot Agentic Workflows 的团队；接入公开渠道的 AI 客服/运维 agent 的 SaaS 公司；安全合规团队

**AI 解决方案**: 扫描 issue/PR/comment 里的隐藏指令（零宽字符、HTML 注释、Unicode 同形字、语义注入）；红队生成 payload 测试自身 agent

**MVP 形态**: GitHub App，装上后扫描指定 repo 所有 issue/PR/comment，标红疑似注入 + 模拟"读到这条会泄露什么"

**变现**: 企业版 ¥999/月/repo；红队测试按次；对标 Snyk 的"AI 输入面安全"新品类

**风险**: Noma Security（发现方）可能产品化 → 须主打国产化+中文社区差异化；企业销售周期长（与睡后收入画像有张力）；提示注入是猫鼠游戏

## 🔥 信号 2: 普通人纠纷"合法取证"辅助工具

**category**: 生活/法律 | **可行性**: 6/10

**证据热点** (2 条，同向):
- [快手] 女子月子期间遭丈夫施暴
- [快手] 男子健身房被女生当众指控偷拍

**底层需求**: 普通人遇到家暴/被诬陷/纠纷时，**不知道怎么合法取证、怎么存证、怎么走流程**才能在维权时站得住。现有法律App重在"找律师/查法条"，缺"事发当下怎么用手机合法取证+云端存证+流程指引"。两条热点都指向同一个底层缺口。

**目标用户**: 家暴受害者、消费纠纷当事人、被诬陷者；妇联/社区调解员作为推荐渠道

**AI 解决方案**:
- AI 能做：根据事发场景生成"取证清单"（拍什么、录什么、保存哪些记录）；证据有效性自检；维权流程导航（报警/申请人身保护令/起诉的顺序）
- 人要做：法律知识库准确性与免责声明、云端存证链路（区块链存证对接）

**MVP 形态**: 微信小程序，选场景（家暴/被诬陷/消费纠纷/交通事故）→ AI 给出取证步骤 + 一键存证（拍照自动上链）+ 流程时间线。先做"取证清单+存证"，不碰律师匹配。

**可行性**: 6/10 — 痛点真实且本周有具体事件；扣分项：变现难（出事才用、低频、付费意愿弱）、法律合规边界（不能越界成"法律服务"）、公益属性重

**变现**: 单次存证 ¥9.9；与妇联/社区合作采购；区块链存证按次；公益版引流付费版

**风险**:
- 低频低付费意愿（出事才用）→ 睡后收入弱
- 法律合规边界（须明确"工具不是法律意见"）
- 公益属性重，商业天花板可能低
- → 建议作为**观察信号**，除非找到付费意愿强的切入角度（如离婚取证、交通事故定责）

## 🔥 信号 3: 个人看片决策 / 烂片避雷助手

**category**: 消费/内容 | **可行性**: 6/10

**证据热点** (6 条同向，content 类集中爆发):
- [豆瓣电影] 寒战1994 (7.0) / 群星闪耀时 (7.4) / 10间敢死队 (6.7) / 群体 (6.2) / 奥德赛 (8.2) / 超级少女 (5.2)

**底层需求**: 一周 6 部新片集中上映，评分 5.2~8.2 跨度大。观众**不知道哪部值得看、哪部是烂片**，豆瓣评分滞后+水军污染。需求是"基于个人口味 + 实时口碑的看片决策"。

**目标用户**: 周末观影人群、豆瓣重度用户、烂片厌恶者

**AI 解决溶液**: 
- AI 能做：聚合豆瓣+短评+预告片，结合用户历史口味（看过/打分过的片）预测"你会打几分"；烂片预警（评分+差评密度+导演历史）
- 人要做：口碑数据采集、个人口味画像

**MVP 形态**: 小程序，输入"想看奥德赛" → AI 基于你豆瓣标记历史预测"你大概率打 7.5 分，值得看"；同步本周新片烂片榜。

**可行性**: 6/10 — 痛点真实、有 6 条同向证据；**扣分项最大：豆瓣/猫眼/知乎已统治看片决策**，差异化窄，且豆瓣有反爬

**变现**: 小程序信息流广告 / 会员去广告（弱）；**睡后收入弱，偏流量生意**

**风险**:
- 豆瓣数据反爬 + 法律边界
- 豆瓣/猫眼/小红书已占位，差异化难
- 流量生意，与 Frank 软件产品画像契合度中低
- → **作为弱信号记录**，不建议投入

## v1 vs v2 对比

| 维度 | v1（tier 采样 120 条） | v2（balanced 采样 104 条） |
|------|---------------------|--------------------------|
| 数据分布 | Tier1=90 / Tier2=30（科技财经主导） | tech=34 / social=34 / news=30 / content=6 |
| 非技术向信号 | 散装山姆薅羊毛 1 条（6/10） | 纠纷取证 + 看片决策 2 条（均 6/10） |
| 最强信号 | GitLost 8/10 | GitLost 8/10（不变） |

| 本周大众内容质量 | — | 一般（多是新闻时政+情绪，可产品化需求密度低） |
