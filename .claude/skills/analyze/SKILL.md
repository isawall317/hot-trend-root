# /analyze — 利基深度分析技能

## 触发

- 用户说 `/analyze`、`analyze`、`分析`、`分析这个`、`深入分析`
- 通常在 `/scan` 后，对感兴趣的信号进行分析

## 执行流程

### Step 1: 确定分析目标

如果用户指定了具体信号/主题，直接分析。否则，从最近一次 scan 结果中推荐 Top 3 值得深入分析的信号，让用户选择。

### Step 2: 多维度信息收集

对目标信号，搜索以下信息（使用 WebSearch + WebFetch）：

1. **需求验证**
   - 搜索引擎关键词搜索量（百度指数、微信指数）
   - 相关社区讨论热度（知乎问题数、小红书笔记数、V2EX 帖子数）
   - 是否有付费产品/服务已经存在

2. **竞争格局**
   - 已有产品/竞品（功能、定价、用户量、用户反馈）
   - 内容供给情况（公众号文章数、知乎回答数、B站视频数）
   - 差异化空间在哪里

3. **商业化潜力**
   - 目标用户画像（谁在为此付费？）
   - 付费意愿证据（已有付费产品的价格/销量）
   - 市场规模估算（不是精确数据，是数量级判断）

4. **执行可行性**
   - 技术方案（浏览器插件 / Web App / 小程序 / AI Agent？）
   - AI 可替代程度（开发、内容、运营各环节 AI 能做多少？）
   - 预计 MVP 工时（AI 辅助下）

### Step 3: 6 维评分

对每个维度打分（1-5 分），并给出理由：

| 维度 | 评分 (1-5) | 理由 |
|------|-----------|------|
| 需求真实性 | | |
| 增长潜力 | | |
| 付费意愿 | | |
| 竞争空间 | | |
| 执行可行性 | | |
| 规模化潜力 | | |
| **综合** | **总分/30** | |

## 评分标准

### 需求真实性
- 5: 大量用户明确表达需求，且愿意付费（有付费产品证据）
- 4: 需求明确，讨论活跃，有付费替代品
- 3: 有一定需求，但缺少付费证据
- 2: 需求模糊，讨论量少
- 1: 几乎没有需求信号

### 增长潜力
- 5: 新兴赛道，增长明显，长期趋势
- 4: 增长中赛道，有明确驱动力
- 3: 稳定赛道，无明确增长信号
- 2: 成熟赛道，增长放缓
- 1: 衰退赛道

### 付费意愿
- 5: 高客单价（>¥500），付费行为已验证
- 4: 中等客单价（¥100-500），有付费先例
- 3: 低客单价（<¥100），用户愿意付费
- 2: 付费意愿弱，用户习惯免费
- 1: 几乎没有付费可能

### 竞争空间
- 5: 几乎没有直接竞品，蓝海
- 4: 有竞品但都有明显缺陷，差异化空间大
- 3: 有成熟竞品，但仍有细分空间
- 2: 竞争激烈，差异化难
- 1: 巨头垄断，几乎没有空间

### 执行可行性
- 5: AI 可完成 80%+ 工作，3-5h MVP
- 4: AI 可完成 60-80%，5-10h MVP
- 3: 需要一定手动开发，10-20h MVP
- 2: 技术难度较高，20-40h MVP
- 1: 需要专业团队，无法单人完成

### 规模化潜力
- 5: 纯自动化产品，零边际成本，睡后收入
- 4: 轻度运营，可半自动化
- 3: 需要持续运营，但可通过 AI 大量替代
- 2: 需要较多人工投入
- 1: 几乎无法规模化，时间换钱
