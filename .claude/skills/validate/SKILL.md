# /validate — 快速验证技能

## 触发

- 用户说 `/validate`、`validate`、`验证`、`验证这个方向`
- 在 `/analyze` 后，对评分 ≥ 20/30 的机会进行验证

## 执行流程

### Step 1: 确定验证目标

从最近分析报告中提取评分 ≥ 20/30 的机会，或用户指定具体方向。

### Step 2: 竞品深度调研

对每个直接竞品，收集：

```markdown
| 竞品 | 产品形态 | 定价 | 用户量/评价 | 核心功能 | 不足之处 |
|------|----------|------|------------|----------|----------|
| {名称} | {插件/Web/...} | {价格} | {数据} | {功能} | {痛点} |
```

### Step 3: 种子用户验证（可选）

如果条件允许，设计一个快速验证方案：

- **小红书/知乎测试**：发一篇相关内容，看 24h 内的互动数据（点赞、收藏、评论内容）
- **搜索量验证**：用 5118/百度指数/微信指数查看关键词趋势
- **已有付费验证**：找到类似产品的付费用户，了解他们的购买动机和不满

### Step 4: MVP 范围定义

如果要开发这个产品，MVP 应该包含什么：

```markdown
## MVP 定义

### 必须做（核心价值）
1. {功能} — 理由: {解决什么核心问题}
2. ...

### 可以不做（等验证后再加）
1. {功能} — 理由: {为什么现在不做}
2. ...

### 技术方案
- 形态: {浏览器插件 / Web App / 小程序 / AI Agent}
- 技术栈: {推荐技术栈}
- AI 可替代: {估计 AI 能完成的比例}
- 预计工时: {AI 辅助下 X 小时}

### 上线渠道
- 主渠道: {Chrome Store / 官网 / 小程序 / ...}
- 冷启动: {小红书发帖 / 知乎回答 / 公众号推文 / V2EX 发布 / ...}
```

### Step 5: Go/No-Go 决策

```markdown
## 决策: 🟢 Go / 🟡 观望 / 🔴 No-Go

### 支撑信号
- ✅ {验证通过的点}
- ✅ ...

### 风险信号
- ⚠️ {不确定的点}
- ⚠️ ...

### 如果 Go
1. 下一步动作: {具体第一步}
2. 预计 MVP 上线时间: {X 天内}
3. 成功标准: {上线后 X 周内达到什么指标算成功}

### 如果 No-Go
- 原因: {为什么放弃}
- 存档: 机会卡存入 data/archive/
```

## 验证原则

- **速度优先** — 验证的目的是快速判断，不是完美调研
- **数据说话** — 不要凭感觉，要有证据
- **敢于 No-Go** — 大部分机会不值得做，放弃是正常的
- **保留机会卡** — No-Go 的机会也存档，未来可能时机成熟
